1. WHAT IS BID BOARD?
================================================================================
Bid Board helps your organisation decide whether to pursue a tender or
opportunity. You capture each opportunity as a project, answer a structured
scorecard, and the app suggests Bid or No Bid based on the overall score (by
default, 70% or above suggests Bid). A senior approver (CSO) then reviews and
confirms the outcome. You can set a pipeline stage on each project, get
deadline reminders, and see history of submissions.

================================================================================
2. YOUR ROLE & CSO APPROVERS
================================================================================
Your administrator assigns one of these access levels in Odoo:

  • Bid Board User — you create and work on projects you are involved in (see
    "Who can see which projects" below).

  • Bid Board Reviewer — same as a user, plus you can open any project and
    related items, which is needed for the review queue and oversight.

  • Bid Board Manager — same as a reviewer, plus access to Configuration
    (settings, email schedule, team list).

Who can click Approve, Decline, or Request change?
That is controlled by email, not only by your access level. Your login email
must be listed under Bid Board → Configuration → Settings → CSO (Email
Approvers). If your email is not on that list, you will not see those buttons
even if you are a Reviewer or Manager. If you need to approve reviews, ask a
manager to add your email there.

If you are on the CSO email list, you will not see Save draft or Submit for
review on the project (those are for the bid team). You will see Approve,
Decline, and Request change when the project is waiting for review or has
changes requested.

================================================================================
3. WHERE TO FIND THINGS
================================================================================
Under the Bid Board app, the main entries are:

  • Leads — CRM leads and opportunities (intake before an enquiry exists).

  • New Enquiry — quick start: name, client, lead, team, deadline, and progress.

  • Bid / No Bid — opens the decision-focused list (default filters and
    workflow context). Sub-menus: All Records — complete list of enquiries;
    Submissions — history of times projects were submitted for review.

  • Review & reminders — sub-menus: Review Queue (only projects that are
    Pending review or Change requested, for approvers); Deadline Reminders
    (reminder records used for emails before submission deadlines).

  • Reports → Project Reports — charts and tables to analyse projects (for
    reviewers/managers).

  • Analytics — one unified Bid Board Analytics screen with tabs: Leads,
    Enquiries, By sales rep, Proposals, and Activity & reminders.

  • Configuration → Settings — who gets emails, CSO list, and related options
    (managers).

  • Configuration → Email Schedule — when automated reminder jobs run
    (managers).

  • Configuration → Team — people you can tag on projects (name, department,
    role, email).

  • Documentation — this help page (last item in the bar).

4. WORKFLOW: START TO FINISH
================================================================================
This is the end-to-end path for one opportunity: where it starts, how it moves
through review, how the enquiry ends, and (when you pursue the tender) how
proposals close the commercial loop.

4.1 Start
---------
Work always converges on an enquiry (a Bid Board project). Typical starting
points:

  • Bid Board → Leads — intake in CRM; use your configured server actions to
    create a linked enquiry when ready.

  • New Enquiry / Bid / No Bid → All Records → New — create the enquiry directly.

  • Bid / No Bid or Bid / No Bid → All Records — open an existing record (parent
    menu uses decision-focused defaults; All Records lists every enquiry).

First to complete: Project info (client, value, duration, scope-of-work % ≤
100%, deadlines, team) and the Scorecard (overall score drives the Bid / No
bid recommendation; default rule uses 70% as the Bid threshold).

4.2 Submit and review
---------------------
  1. Bid team: Submit for review → Pending review. Each submit is logged under
     Bid / No Bid → Submissions.

  2. CSO (email on Configuration → Settings → CSO approvers): Approve,
     Decline, or Request change. Use Review & reminders → Review Queue if you have access.

  3. If Request change: team edits, then Submit for review again.

If your organisation enabled a submit threshold, submission may be blocked
until the overall score reaches the minimum.

4.3 How the enquiry ends
------------------------
  • Approved + Bid — review is Approved; final decision Bid; project state
    becomes Completed. You may create proposals next.

  • Approved + No bid — approved with No bid; project state Declined. No
    proposal path.

  • Review declined — CSO Declined the submission; record is locked for typical
    users per your access rules.

  • No submission — enquiry stays in Draft or is left inactive (operational
    choice).

4.4 Proposals (after Bid)
-------------------------
When the enquiry is Approved with Bid, open it from Bid / No Bid and use Create
proposal. Defaults (including Scope of work from enquiry) flow from the
enquiry.

End of proposal workflow: set outcome to Won or Lost on the proposal. The
enquiry remains the permanent Bid / No bid record.

4.5 Diagram (overview)
----------------------
START → Lead / New enquiry / Open enquiry
          ↓
     Project info + Scorecard
          ↓
     Submit for review → Pending review
          ↓
   ┌─────┴─────┬──────────────┐
   ↓           ↓              ↓
Decline    Request change    Approve
   ↓           ↓              ↓
 END       edit & re-submit   final decision Bid or No bid
                 ↓                    ↓
                loop          No bid → END (enquiry declined)
                                    Bid → Create proposal → Open → Won/Lost → END

5. STATUSES & DECISIONS
================================================================================
Pipeline stage
--------------
Each project has a stage such as New, Qualified, Proposition, or Won. Stages
describe where the opportunity sits in your sales process. Stage is separate
from review status (draft vs pending CSO, etc.).

Project status
--------------
  • Active — work in progress.

  • Completed — CSO approved and the final decision was to Bid.

  • Declined — CSO declined the review, or the final decision was No bid after
    approval.

  • Priority — mark important deals; you can set this when creating or editing a
    project.

Review status
-------------
  • Draft — the team is still editing; use Save draft if you want to record
    that explicitly.

  • Pending review — submitted to CSO; waiting for Approve, Decline, or Request
    change.

  • Change requested — CSO asked for updates; adjust the project and submit
    again.

  • Approved — CSO signed off; the project may be read-only for the team until
    a CSO edits it.

  • Declined (review) — CSO rejected the submission; the record is locked like
    an approved one (only CSO, Bid Board managers, or administrators can change
    or delete it).

Bid vs No bid
-------------
The app sets Bid when the overall score is at least 70%, otherwise No bid. That
final decision drives the wording on the sheet and what happens after approval.

================================================================================
6. STEP-BY-STEP WORKFLOW
================================================================================
  1. Create a project — use New Project or copy an existing one. The app
     assigns a reference code such as BID-#####.

  2. Project info tab — fill client, location (emirate), industry, contract
     details, bonds, KPI, scope percentages (they must add up to at most
     100%), deadlines, team, and notes.

  3. Scorecard tab — lines are added automatically for new enquiries (defaults
     start at the top score so you can submit once content is right; lower any
     row to reflect risk). Pick 1, 2, or 3 per line and weights; add short
     comments if helpful.

  4. Decision sheet tab — check category scores, overall score, and the Bid /
     No bid recommendation from the score rule.

  5. Submit for review — sends the project to CSO. A line appears in
     Bid / No Bid → Submissions. CSO may get an email depending on your company settings (see
     below).

  6. CSO chooses Approve, Decline, or Request change (with comments and
     priority). Approving notifies commercial/bid contacts and optionally the
     person who created the project.

  7. After approval — status becomes Completed if the final decision is Bid, or
     Declined if it is No bid. Any open change requests are closed.

  8. If CSO requests changes, you get an email, update the project, and click
     Submit for review again.

On each project you can use the log at the bottom to leave messages and
schedule activities like any other Odoo record.

================================================================================
7. PROJECT SCREEN (TABS & BUTTONS)
================================================================================
Top buttons
-----------
  • Save draft and Submit for review — for bid team members (not CSO
    approvers).

  • Approve, Decline, Request change — for CSO approvers (email on the CSO
    list, with reviewer/manager access).

  • The status bar shows where the review is: Draft → Pending review → Change
    requested → Approved or Declined.

Project info tab
----------------
Everything about the deal: title, reference code, client, sales rep, project
lead, team tags, emirate, industry, contract length and value, type, risk
threshold, tender and performance bonds, KPI, deadlines, progress, high-level
status, and pipeline stage.

Scope of work (%)
-----------------
Split the work mix across cleaning, maintenance, security, landscaping, laundry,
support, and other. The total must stay at or below 100%.

================================================================================
8. FILLING IN THE SCORECARD
================================================================================
Criteria are grouped under Strategy, Customer, Commercial, Finance, and
Operations. Each row has three wording options (columns 1–3); you pick the
level 1, 2, or 3 that best matches the opportunity and set a weight if some
factors matter more.

The app turns that into category scores and one overall score. New and
duplicated enquiries get a standard set of scorecard rows automatically; you
can edit them as needed.

================================================================================
9. DECISION SHEET
================================================================================
Here you see the five category scores (read-only), the overall score, short
recommendation text, the Bid / No bid outcome from the score rule, and review
status.

================================================================================
10. CSO: APPROVE, DECLINE, OR REQUEST CHANGES
================================================================================
  • Approve — closes the review as approved, records who approved and when,
    sets project status to Completed (Bid) or Declined (No bid), closes open
    change requests, and sends notification emails per settings.

  • Decline — marks the review declined and the project declined; notifies
    lead, creator, and managers as configured.

  • Request change — opens a short form for priority and comments; the project
    goes to Change requested and the creator gets an email with your notes.

After Approval, team members who are not on the CSO email list usually cannot
edit or delete the project; CSO approvers still can if something must be
corrected.

================================================================================
11. SUBMISSIONS, CHANGES & DEADLINE REMINDERS
================================================================================
Submissions
-----------
Each time someone clicks Submit for review, a submission line is created with the
date and owner. View the list under Bid / No Bid → Submissions or on the project’s
Submissions tab.

Change requests
---------------
When CSO asks for changes, those requests appear on the project with priority
and comments. They are marked resolved when the review is completed.

Deadline reminders
------------------
The system can send emails 7 days, 3 days, and 1 day before the submission
deadline to the project lead and, where set, selected team members. Approved
or declined projects stop receiving these reminders. Details of sent reminders
may appear on the reminder record and in the project log.

================================================================================
12. EMAILS & AUTOMATIC REMINDERS
================================================================================
When emails are sent (typical setup)

  • Submit for review — to CSO addresses when “notify on every submission” is
    on, or when the score is above 80% if that option is off (exact behaviour
    is set in Settings).

  • Approval — to commercial and bid managers, and optionally the person who
    created the project.

  • Decline — to project lead, creator, and managers as configured.

  • Change requested — to the project creator.

  • Test email — from Settings, to check that notifications look correct.

Bid Board needs a valid “from” address in Settings or in your organisation’s
general outgoing mail settings in Odoo. If sending fails, a note may appear on
the project’s log explaining why.

Automated daily checks (managers can see timing under Email schedule)

  • Governance reminder — reminds CSO if a project has waited too long for
    review (based on Pending review SLA days in Settings) or if a follow-up
    activity is due soon.

  • Deadline reminders — sends the T-7 / T-3 / T-1 emails described above.

================================================================================
13. SETTINGS (MANAGERS)
================================================================================
Open Bid Board → Configuration → Settings. There should be only one settings
record—edit it, do not create extra copies.

  • Notification from — the sender name and address on Bid Board emails.

  • CSO (Email approvers) — who may use Approve / Decline / Request change
    (comma-separated emails).

  • Notify CSO on every submission — if turned off, CSO is emailed mainly when
    the score is high (above 80%).

  • Submit threshold — open Bid Board → Configuration → Submit Threshold and
    set a percentage (technical key: sales_bid_board.submit_review_min_score).
    Users can submit for review only when overall score is at or above this
    value.

  • Commercial manager email and Bid manager email — who gets approval/decline
    notifications (you can list several addresses separated by commas).

  • Notify creator on approval — optional copy to whoever created the project.

  • Pending review SLA days — how many days’ wait triggers a governance
    reminder to CSO.

  • Test recipient and Send test email — check that mail works before go-live.

================================================================================
14. WHO CAN SEE WHICH PROJECTS
================================================================================
Users normally see projects they created, lead, sell, or are on as a linked
team member (with an Odoo user on that team entry).

Reviewers and managers can open all projects and related submissions,
reminders, and change requests—needed for oversight and the review queue.

Managers also maintain settings, the team directory, and can review the email
schedule.

================================================================================
15. REPORTS & ANALYTICS
================================================================================
Project reports lets you build pivot tables, charts, and lists of projects—
filter by status, review stage, group by pipeline stage or lead, and so on.

Bid Board Analytics is a single tabbed dashboard for leadership. Each tab
supports filters and drill-down to lists/forms from KPIs, charts, and table
rows: Leads, Enquiries, By sales rep, Proposals, and Activity & reminders.

Proposals also show Scope of work (from enquiry), which flows from the linked
Bid / No Bid enquiry so commercial users always see the same scope split.

16.2 CSO actions (table)
------------------------

  Action          Result
  --------------  ----------------------------------------------------------
  Approve         Review Approved; state Completed (Bid) or Declined (No bid);
                  change requests closed; notifications per settings.
  Decline         Review declined; project declined; notifications per settings.
  Request change  Review status Change requested; team resubmits.

16.3 Enquiry end states (table)
---------------------------------

  End state              Meaning
  ---------------------  ------------------------------------------------
  Approved + Bid         Completed; may create proposals.
  Approved + No bid      Declined; no proposal path.
  Review declined        Locked for typical users per rules.
  Stopped without submit Draft or inactive; no CSO decision.

16.4 Supporting processes (table)
---------------------------------

  Area                 Role
  -------------------  --------------------------------------------------
  Deadline reminders   T-7 / T-3 / T-1 emails while active (config).
  Change requests      On enquiry; resolved when review completes.
  Bid Board Analytics  Drill-down reporting.
  Project Reports      Pivot/list on enquiries.
